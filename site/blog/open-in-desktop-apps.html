Open a chat straight in the Claude or Codex app

7 Nov 2026 · by @heyvamz

Three releases today (0.4.2 to 0.4.4), all from testing carry with a friend on two laptops. The theme: fewer steps between "my friend sent me a chat" and "I'm working in it".

Open in the desktop apps

Until now, a shared session opened in Claude Code or Codex through their terminal commands. If you only had the apps, the session was written but the app never showed it. Now:

$ carry open 1 --to claude_app # the Claude app's Code tab $ carry open 1 --to codex_app # the Codex app

It is the same full session, every message and dead end, opened through each app's own link. With the connector installed you don't need the terminal at all: ask Claude "open item 1 from my carry inbox in the Code tab".

The terminal targets got easier too. No codex command? carry uses the one inside ChatGPT for Mac, or runs it with npx. Same for claude.

Pairing codes, four times shorter

A pairing code used to be about 270 characters. It is now about 63, like carry2.1WVG…dTOdo.z0Kl…PNMw. Your name and the rest moved inside the encrypted inbox, so the code only says where that inbox is plus a secret. Old codes still work.

Tab completes your chats and friends

carry setup now turns on Tab completion for zsh, bash and PowerShell, so macOS, Linux and Windows. Open a new terminal, type carry open and press Tab to see your shares, or --to and Tab for friends and apps. Skip the name entirely and carry lists the newest few to pick by number.

Smaller fixes

Deleted the carry folder in Drive? Sharing used to fail with "File not found"; carry now makes a new one. Your own shares open by name, no Drive link needed. And a mistyped command no longer prints the help text into a file you redirect to.

Update with carry update, then run carry setup once to turn on Tab completion. Full list in the changelog.
